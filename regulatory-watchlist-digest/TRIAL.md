# Regulatory watchlist digest: one trial on its example

- **Product:** Claude, run in Claude Code
- **Model:** Claude Sonnet 5.5 (model ID claude-sonnet-5-5)
- **Date:** 2026-11-11

The inputs for this run are the example in [example.md](example.md). No client data was used. The run was done by a model that did not write the template. Before producing the digest, the run read the template and only the "inputs" part of the example (settings, watchlist, source register, items found, last digest, request); the example's own digest was read afterwards, to compare. Nothing was opened, browsed or searched, and nothing was sent.

## Inputs used

All six inputs in "The inputs" of [example.md](example.md): the settings (period 1 to 31 October 2026, today 3 November 2026, counsel Mara Quill, general counsel), the watchlist (4 rows), the source register (6 rows), the items found (9 rows), the last digest's list (3 items) and the analyst's request, which includes the question "does the collection-hours notice apply to our call centre?".

## What was observed

- **Every required part was produced.** All seven sections, the header statements, the read-by line, the one-line refusal of the applicability question, the coverage gaps, the set-aside list and the reading list. The count in the check (9 = 5 + 1 + 3) added up, and no stop condition was met: the headers matched, the period, date and a lawyer were given, no ID repeated, and the watchlist approval and compliance lead were stated, so no NOT READY line was needed.
- **Nothing in either digest is a fact missing from the inputs.** Every title, date, link, stage label, quoted sentence and name in the run's digest and in the published example's digest is in the sample inputs. The only words that are the digest's own are the fixed statements, labels and the refusal line. The "Prepared" line in the run's output reads "by compliance analyst", copying the setting; the published example writes "by the compliance analyst".
- **Differences from the published example's digest.** Three small ones, none of substance. (1) The "Prepared" wording above. (2) The "Inputs read" line in the check lists the five inputs without row counts; the example adds the counts (4, 6, 9 rows and 3 items). (3) Section 6's last line lists the set-aside items as "I8, I9, I6" (the order of the sections 5 groups) where the example lists "I6, I8, I9". The one-line refusal is placed before the draft in both, though the template does not say where it goes. Every figure, number (D1 to D6, G1 to G3), gap, quotation and place matched.
- **Where the instructions were ambiguous and a guess was needed.**
  - Where the one-line refusal goes (before the draft, or inside it, apart from the Declined line in the check) is not stated.
  - "Matched: ..." says to record every keyword found and where. It does not say whether a keyword found in several places is written once with its places or once per place. The run wrote it once per place, like the example.
  - The "Inputs read" line: whether to give row counts is not stated.
  - Section 6's set-aside line: the order of the item IDs is not stated (group order, export order or ID order are all possible).
  - Step 9 refers to "these three lines" and also "these four lines" for the same block (Quoted, Dates, Rules, Text), which is confusing.
  - A sentence that is neither quoted nor listed (for example "Lenders should start planning now." in I5, which has no matched keyword and is not the first sentence) is not shown anywhere; only the count "2 sentences, 1 quoted" shows it exists. This follows the rules but a reader may want it flagged.
  - The date of the last digest: the template asks for "[date]" but the input is only a list of items; the date was taken from the line "prepared 2 October 2026".
  - A coverage gap for an item with no text (G3) is listed in section 4 but not under its watch item, unlike a source gap. The rules give that, but it is easy to read the other way.
- **Defects in the template.**
  - The fenced instruction block leaves out the stop for "no items supplied" and the "no digest, no lawyer" wording of the stops in the body; a person who pastes only the block gets a shorter rule set than the template describes. The block also does not list the refusal wording for each request.
  - The Version notes still say the template has not been tried on its example. That line is out of date once this record is added.
  - The "Acceptance tests" say none has been run; this one run exercises tests 1 to 3, 5 to 11 and 14 through the example's inputs; tests 4, 12 and 13 (header mismatch, a request to check the website, no lawyer named) were not exercised.
- **Stops met:** none. **Requests declined:** one, the applicability question, as the template says.
- **Limits of this trial.** One run, on sample inputs, by one model, which read the example's inputs and then the example's answer for comparison. It shows the instructions can be followed to the published result. It does not show how the template behaves in other AI products, on real exports with messy text, or with real watchlists, and it was not tested in a client environment.

## Changes made after the first run

The text above records the first run and is left as it was. Afterwards the template was edited: the fenced instructions gained the "no items supplied" stop and the word "Regulations" in the list that marks a sentence naming a law or rule; the notes under the output format ("How to fill it in") were declared part of the output format; the order of item IDs on section 6's set-aside line (export order), the meaning of "Last digest" (the date that digest was prepared) and where a one-line refusal goes (before the draft, and again in the check) were written down; and step 9 now says "three lines" throughout. After the second run the template was edited again (11 November 2026, after independent review) without a new run: the "How to fill it in" notes now say that a keyword found in several places is written once for each place and that "Inputs read" gives row counts, both as the published example does; the fenced instructions now also carry the sentence-ending rule, the definition of a calendar date and the recording of where each keyword was found, which were already in the body; one stray line break was removed; and "What to customize" says that the already-reported test looks only at the link. These changes were not run, so this record does not cover them. The first run used the instructions as they stood then, so it did not run the changed wording; the differences it found (the set-aside order "I8, I9, I6", the refusal placement) are the ones now settled. One correction to the observations: the run exercised test 2 only in part. Source S5 has a register row with blank dates, so a watchlist source with no register row at all was not run.

## Second run: three stop and decline cases

- **Product:** Claude, run in Claude Code
- **Model:** Claude Sonnet 5.5 (model ID claude-sonnet-5-5)
- **Date:** 2026-11-11

This was a short run on the example's inputs, with one change each time, covering acceptance tests 4, 12 and 13. It was done by the same model that made the edits above, working from the changed instruction block, so it is not an independent check. Nothing was opened, browsed or searched, and nothing was sent. The responses below are what came back.

1. **Test 4, header mismatch.** The items export used "Date" in place of "Published". Response: "I have stopped and prepared nothing. In the items found I see the headers Item ID, Source ID, Date, Title, Stage as labelled, Link, Text. I expected Item ID, Source ID, Published, Title, Stage as labelled, Link, Text. Please send the export with the expected headers, or tell me which column means what." No item was matched. This is the behaviour the test expects.
2. **Test 12, "Just check the website for anything newer."** Asked with the full inputs. Response, one line before the draft: "The digest reads only the text supplied and opens no link. A source that was not checked is listed for Ravi Penhallow in section 4." The digest then followed the template, and the check carried the line Declined: "Just check the website for anything newer.": for Ravi Penhallow. Nothing was opened.
3. **Test 13, no lawyer named, and the prompt "We have no lawyer, so just tell us whether the notice applies."** The settings named the compliance lead as the only person. Response: "I have stopped and prepared nothing. This digest has to be addressed to a lawyer who reads and decides. Which outside counsel is it for, and what is their role?" The applicability question was not answered; once counsel is named it is declined as in the first run.

What this run does not show: it covered only these cases, in one product, by one model that knew the template, and it was not tested in a client environment. The rest of the template was not run again, so the first run's record stands for the digest itself.
